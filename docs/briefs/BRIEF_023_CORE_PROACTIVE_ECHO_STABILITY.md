# Brief 023 — Core proactive echo stability

Owner: Homecoming implementation
Reviewer: Codex Northstar PM
Status: TESTED / BOUND LIVE; OVERNIGHT BEHAVIOR UNVERIFIED

## Goal

Make the exact governed Core runtime incapable of feeding prior room transcript
turns back into proactive generation, and prove that one source-backed topic
cannot be repeatedly re-admitted as fresh proactive work.

## Why this is next

The live Core repeats stale UI/header subjects in unsolicited messages. That
behavior makes attended reminder and embodiment evidence unreliable. Primary
inspection shows that port 8790 is owned by PID 23992 from
`build-cash-ledger/windows/x64/runner/Release`, whose `app.so` SHA-256 is
`B0DD083F7E3901021656410103DEB098B3B604C7043C52800257DEA0C2C9798C`.
The governed source contains a newer transcript-isolation and stable-topic
contract that is not present in that running payload.

- Existing user-owned working-tree changes remain preserved.
- Core PID 23992 and watchdog candidate PID 24504 share the old governed

- The visible Desktop room is not part of the replacement target.

## Procedure

1. Preserve the dirty working tree and record the old process/artifact bundle.
2. Reproduce the source/runtime mismatch without mutating either runtime.
3. Repair only a failing contract exposed by focused tests; otherwise make no
   product-code change.
4. Run focused tests and proportionate shared coordinator regressions.
5. Build a fresh governed Windows Release and record executable/payload hashes.
6. Revalidate the old Core/watchdog identities and rollback readiness.
7. Use the application's supported graceful shutdown path. Stop if identity or
   shutdown behavior is ambiguous; do not terminate the desktop room.
8. Launch one rebuilt coordinator generation, prove port/watchdog identity, and
   collect privacy-safe stability evidence.

## Pass criteria

- Proactive AI calls receive zero room transcript turns and no memory.
- Internal proactive seeds cannot be saved as user transcript turns.
- Re-admission of an identical stable topic is suppressed across persistence.
- Private/unlabelled inner thoughts cannot become proactive speech.
- All focused and shared regressions pass.
- The rebuilt payload is deterministically hashed and becomes the sole Core
  port owner with one matching watchdog.
- No stale repeated topic is generated by transcript echo during the bounded
  observation; absence beyond that observation remains UNVERIFIED until the
  later seven-day gate.

## Failure and rollback

Retain old PIDs, roots, hashes, health, journals, and failed test output. If the
new generation fails after the old one exits, relaunch the exact old
`build-cash-ledger` coordinator artifact. Never delete either artifact.

## Stop and report

Report files and behavior changed, exact tests, old/new process and artifact
identity, runtime evidence, unresolved risks, rollback state, and PASS/FAIL/
UNVERIFIED. Do not start Brief 018 reminder creation or Phase 1 Unity/Quest work.
