# Table Ready — Session Zero & Group Compatibility Kit

Version 1.0 — 2026-08-09

## Buyer and promise

For a GM or host forming a tabletop role-playing group with strangers, new
friends, or loosely connected players. In 30–45 minutes, compare the things
that usually break a group later — schedule, commitment, play style, tone,
boundaries, accessibility, communication, and location — and write one clear
table agreement before anyone commits to a campaign.

This is a conversation and decision aid, not a personality test, safety
guarantee, background check, matchmaking service, rules supplement, or legal,
medical, accessibility, or safeguarding advice.

## Page 2 — Quick start

Use this before a campaign, recurring game night, or paid table.

1. Each person completes pages 3–8 privately or in quiet time.
2. Share only what you are comfortable sharing. A boundary needs no explanation.
3. The host records the group pattern on pages 9–12.
4. Resolve mismatches with a specific adjustment, not vague optimism.
5. On page 13 choose: READY, READY WITH CHANGES, or NOT THIS TABLE.
6. Review the agreement after the first session and after 30 days.

Ground rules:
- No answer is a promise that circumstances will never change.
- Do not pressure anyone to explain a boundary or access need.
- Compatibility is not a score. One critical mismatch can matter more than ten matches.
- “Not this table” can be a healthy outcome.

## Page 3 — My player snapshot

Name or table name; pronouns optional; contact method; age-band confirmation;
experience; systems/genres wanted; systems not wanted; languages; what a great
session feels like; what usually makes me stop attending.

## Page 4 — Schedule reality

Timezone; available days; earliest/latest start; session length; frequency;
earliest start date; expected end/commitment; blackout dates; travel time;
minimum notice; acceptable reschedule window; likely attendance percentage;
what happens if I am late/absent; red-line schedule constraint.

## Page 5 — Format, venue, and access

Online / public venue / private venue only with explicit agreement / hybrid;
travel radius; transport/parking; stairs/seating/noise/light; restroom/breaks;
food/allergy considerations; camera/microphone; screen reader/captions/text chat;
sensory needs; service animal; alcohol/smoking environment; cost ceiling;
privacy about access needs; host follow-up required.

## Page 6 — Game promise

System; campaign/one-shot; genre; tone; rating/content level; expected arc;
character creation constraints; rules approach; homebrew; death/failure stakes;
prep/homework; technology; source ownership; recording/streaming; AI-generated
material disclosure; payment/refund if any; what is explicitly excluded.

## Page 7 — Play-style compass

Mark preference from 1 to 5:
- tactical challenge ↔ freeform story
- serious consequences ↔ light/casual
- GM-led direction ↔ player-led exploration
- rules as written ↔ flexible rulings
- long character scenes ↔ fast scene changes
- cooperative spotlight ↔ competitive edge
- planned campaign ↔ improvisational sandbox
- high difficulty ↔ comfort-forward play

Then choose three must-haves, three flex points, and one deal-breaker.

## Page 8 — Commitment and communication

Arrival standard; cancellation notice; repeated no-show response; between-game
messages; response-time expectation; scheduling owner; decision method; conflict
path; feedback preference; device use; side conversations; substances; guests;
sharing contact details; photos/recording; public posts; payment deadline/refund;
exit without drama; reliability promise I can honestly make.

## Page 9 — Boundaries without interrogation

For each topic use: OKAY / ASK FIRST / FADE OR SKIP / HARD NO / PRIVATE.
Categories: graphic violence; harm to children; sexual content; romance;
discrimination/prejudice; body horror; illness/medical themes; grief/death;
phobias; loss of control; player-vs-player conflict; secrets/betrayal; substance
use; religion/cults; real-world politics; other.

In-play stop language; private check-in method; who can pause; how content is
changed; incident follow-up; confidentiality boundary. A person may change an
answer at any time. This worksheet reduces ambiguity; it cannot guarantee safety.

## Page 10 — Compatibility map

Group rows: schedule, frequency, format/location, cost, system/genre, tone,
play style, commitment, communication, boundaries, accessibility, recording/
privacy. Columns: aligned; workable change; unresolved; owner; due date.

Rule: “We’ll figure it out” is unresolved unless an owner and date are written.

## Page 11 — Mismatch repair

For each mismatch: what differs; why it matters; smallest change; who bears the
cost; trial period; success signal; review date; fallback. Fairness check:
voluntary, specific, reversible where possible, no boundary explanation needed,
does not isolate one person, actual resource/owner exists.

## Page 12 — Table agreement

Our game promise; schedule; location/platform; attendance/cancellation rule;
communication channel and response window; decision method; rules/rulings;
spotlight and device norms; boundary/pause method; access arrangements;
recording/privacy; payment/refund; conflict path; exit path; review date;
participants acknowledge this is current and revisable.

## Page 13 — Decision

READY — critical needs align; next action/date/owner.
READY WITH CHANGES — list each change, owner, deadline, trial, review.
NOT THIS TABLE — mismatch and respectful close; do not argue a boundary.

Private confidence 0–10; strongest reason; what proof/experience would change
the decision; first-session check-in; 30-day check-in.

## Page 14 — Host facilitation guide

Before: send pages 3–8; identify private-response route; state offer and price;
do not promise universal fit. During: start with schedule/cost; summarize, do
not diagnose; separate preferences from boundaries; document owners/dates; let
anyone pass. Close: read agreement; ask private confidence; name unresolved
items; make explicit decision. After: share only agreed record; delete private
notes; review after first session; record changes.

Useful phrases:
- “You do not need to explain that boundary.”
- “Is this a preference, a need, or a hard condition?”
- “What specific change would make this workable?”
- “Who owns that change, and by when?”
- “Not this table is an acceptable result.”
